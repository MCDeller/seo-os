# {{PORTAL_TITLE}} — SEO Office portal

This folder is the portable home of the **{{PORTAL_TITLE}}** SEO Office portal.
Everything you care about lives here; the app engine that runs it lives inside
Ubuntu at `{{ENGINE_DIR}}` and can always be rebuilt.

## Daily use

Open Ubuntu (Start menu → **Ubuntu**, or `wsl -d Ubuntu` in PowerShell), then:

```
seo-{{PORTAL_NAME}}
```

(or `bash "{{PORTAL_HOME}}/start.sh"`). Open **http://localhost:{{PORT}}** in
your Windows browser. Leave the Ubuntu window open while you work; press
`Ctrl+C` in it to stop. Each start first saves a database backup.

## What is where

| Path | What | Safe to edit by hand? |
|---|---|---|
| `clients/<slug>/` | Each client's brain (markdown, `marketing-brain.v1`). Open in VS Code or Obsidian. | Read freely. Edit notes carefully — keep the frontmatter. Never delete a client folder by hand; use the app. |
| `source-docs/<slug>/` | **Your** original documents for that client. The app never reads or changes this folder. | Yes — it is yours. |
| `config/portal.env` | API keys and settings for this portal only. **Contains secrets.** | Yes (or use the `/setup` page). Restart after editing. |
| `config/gcp-oauth-client.json` | This portal's Google OAuth client. **Secret.** | Replace via `/setup` or by hand. |
| `config/portal.conf` | The definition this portal was built from. | Edit, then re-run setup. |
| `backups/` | Copies of the portal database (`index.db`), last 20 kept. | Yes. |
| `start.sh`, `backup.sh`, `README.md` | Generated by setup. Re-running setup rewrites them. | No — edit `portal.conf` and re-run setup. |

> Don't put source documents inside `clients/<slug>/.raw/` — that folder is the
> app's own cache and files older than 30 days are deleted automatically.
> Converting documents from `source-docs/` into brain notes
> (`clients/<slug>/wiki/sources/`) is a separate, deliberate step.

## Google setup (one-time, signed in as {{GOOGLE_ACCOUNT}})

Use an **Incognito / InPrivate window** signed in only as {{GOOGLE_ACCOUNT}}, so
no other Google account is picked by mistake.

1. **Cloud project.** <https://console.cloud.google.com> → create a project for
   this portal (e.g. `seo-office-{{PORTAL_NAME}}`).
2. **APIs.** APIs & Services → Library → enable: *Google Search Console API*,
   *Google Analytics Data API*, *Google Analytics Admin API*, *PageSpeed
   Insights API*, *Chrome UX Report API*.
3. **OAuth consent screen.** External (or Internal for Workspace accounts); add
   {{GOOGLE_ACCOUNT}} as a test user while the app is in Testing.
4. **OAuth client.** Credentials → Create credentials → OAuth client ID →
   *Desktop app* → download the JSON → upload it on the portal's `/setup` page
   (it is saved to `config/gcp-oauth-client.json`).
5. **API key.** Credentials → Create credentials → API key → restrict it to
   PageSpeed Insights + Chrome UX Report → paste it on `/setup`.
6. **Sign in.** On `/setup`, Google Cloud card → sign in → copy the link into
   your Incognito window → approve as {{GOOGLE_ACCOUNT}}.
7. **Access.** {{GOOGLE_ACCOUNT}} must be an owner/full user of each client's
   **Search Console** property and at least Viewer on each **GA4** property.

This portal's Google sign-in is stored in `{{ENGINE_DIR}}/.gcloud`, separate
from every other portal and from your normal `gcloud` login.

## Backups and restore

- `bash "{{PORTAL_HOME}}/backup.sh"` makes a backup any time (start.sh does it
  automatically).
- To restore: stop the portal, copy a file from `backups/` to
  `{{ENGINE_DIR}}/.seo-office/index.db`, start the portal.
- The client brains in `clients/` are plain files — back up this whole folder
  with whatever you use for D: (it contains secrets in `config/`, so keep those
  backups private).

## Moving to another PC

1. Copy this whole folder to the new PC (same path is simplest).
2. On the new PC install Ubuntu (WSL2), then Node 24, pnpm, Python 3, git and
   the Google Cloud CLI.
3. Clone the SEO Office repo and run, from inside it:
   `bash scripts/portal/setup-portal.sh "<this folder>/config/portal.conf"`
   (edit `PORTAL_HOME` in that file first if the path changed).
4. Setup rebuilds the engine, re-links `config/portal.env`, re-indexes the
   brains in `clients/`, and leaves your keys and brains untouched.
5. Sign in to Google again on `/setup` (sign-ins are deliberately not copied).
